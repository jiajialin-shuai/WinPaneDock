# M1.1 Profile

状态：2026-09-23 完成。

## 使用

运行 `spikes/M0.Terminal.Wpf/bin/Debug/net8.0-windows/Cmux.Spike.Terminal.exe`。首次安装启动会自动建立 Group 并启动默认的 PowerShell 7；顶部可切换 Profile，新 Group 和 Split 会用当前选择启动。空 Pane 可以在右上角设置面板中点击 **Start selected profile**。首次运行会生成 `%LOCALAPPDATA%\cmux\profiles.json`；同一设置面板中的 **Edit profiles.json** 可用记事本修改，保存后重新打开 cmux 加载配置。`Custom` 的 `command` 默认留空，填写后即可选择启动。

Profile 是 JSON 数组，每项使用路线图约定的四个字段：`name`、`command`、`args`、`startingDirectory`。`args` 是字符串数组；`startingDirectory` 为空时，新 Group 使用 Workspace Root，Split 优先继承原 Pane 当前目录；也支持 `%USERPROFILE%` 等环境变量。内置 Profile 依赖对应 Shell 已安装；Git Bash 默认寻找 Program Files 下的 Git 安装，必要时可在 JSON 中改路径。

可用 `--profile "PowerShell 7"` 直接启动指定 Profile。M0 的 `--cmd "..."` 参数仍可用于探针，并优先于 `--profile`。

## 验收

1. `dotnet build spikes/M0.Terminal.Wpf/M0.Terminal.Wpf.csproj --no-restore`：0 警告、0 错误。
2. 不带参数启动：Profile 选择栏显示；截图见 `artifacts/m1.1-profile-picker.png`。
3. 分别使用 `--profile` 启动 PowerShell、PowerShell 7、CMD、Git Bash、WSL：本机均生成对应的 `powershell.exe`、`pwsh.exe`、`cmd.exe`、`bash.exe`、`wsl.exe` 子进程和 `OpenConsole.exe`。
4. 临时将 Custom 设为 `cmd.exe`，参数写入当前目录，`startingDirectory` 指向 `docs`：标记文件内容为仓库中的 `docs` 绝对路径；随后恢复配置。
5. M1 阶段通过关闭主窗口结束进程；M5 起关闭主窗口会保留 SessionHost 和 Shell，显式 Close/Kill 才结束对应会话。

上面的验收是 2026-09-23 M1.1 阶段记录；当前运行中可以切换 Profile，重启和配置编辑入口位于右上角设置面板。
